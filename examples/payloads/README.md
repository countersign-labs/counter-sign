# Conformance vectors

These are canonical, **really-signed** Countersign envelopes. They are the
interop test set: an independent implementation of the protocol should be able
to verify every one of them and to reject tampered variants. They are
regenerated by `npm run gen:payloads` and validated by the test suite against
the JSON Schemas in [`../../schemas/`](../../schemas/).

| File | Artifact | Must verify as |
| ---- | -------- | -------------- |
| `intent.example.json` | Intent (`quorum` 1) | `verifyIntent` → **true** |
| `intent.quorum.example.json` | Intent (`quorum` 2) | `verifyIntent` → **true** |
| `countersignature.approve.example.json` | Countersignature, human approve | `verifyCountersignature` → **true** |
| `countersignature.reject.example.json` | Countersignature, human reject | `verifyCountersignature` → **true** |
| `countersignature.default-timeout.example.json` | Countersignature, timeout Default (`actor: default:timeout`, `policy: default`) | `verifyCountersignature` → **true** |

## How to verify

Each payload is **self-contained**: it embeds the base64url ed25519 public key
that signed it (`agent.public_key` for an Intent, `public_key` for a
Countersignature). No external keys are needed to check integrity.

A conforming verifier MUST:

1. Remove the `signature` field.
2. Serialize the remaining object as **canonical JSON** — object keys sorted
   lexicographically at every depth, no insignificant whitespace, UTF-8.
3. ed25519-verify `signature` over the bytes `context || 0x0A || canonical`,
   where `context` is the artifact's domain-separation label:
   - Intent → `countersign-intent-v0.1`
   - Countersignature → `countersign-countersignature-v0.1`
   - (email decision link → `countersign-link-v0.1`)
4. Consider the payload valid only if that check passes.

See spec §1 (signing) and §3 (verification) in
[`../../spec/countersign-spec.md`](../../spec/countersign-spec.md).

## Negative checks

A conforming implementation MUST reject:

- any payload with a mutated field (e.g. changing `summary` or `decision`) —
  the signature no longer verifies;
- a Countersignature verified under the Intent context, or vice versa — domain
  separation makes a signature valid only for its own artifact type;
- acting on a Countersignature on the strength of integrity alone: **integrity
  is not authority.** The signer's `public_key` must also be in a trusted set
  for the Route (spec §3).

The test suite exercises all of these; see `tests/signing.test.ts`,
`tests/schemas.test.ts`, and `tests/security.test.ts`.
